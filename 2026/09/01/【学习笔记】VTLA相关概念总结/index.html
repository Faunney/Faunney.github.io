【学习笔记】VTLA相关概念总结

Created2026-09-01|Updated2026-09-17|学习笔记
|Word Count:2.9k|Reading Time:9mins|Post Views:

问题背景

  • 关于Lerobot：

    • 是HuggingFace推出的机器人学习开源库，标准化机器人策略学习相关数据集与代码，统一数据格式和训练流程，方便开发者进行复现与改进。
    • 几个关键统一：
    • 统一数据集格式，用LeRobotDataset(“xxx/xxx”)可直接加载
    • 策略库：把ACT、DiffusionPolicy、VLA类模型等策略实现内置到Lerobot中，可直接调用，都是标准化接口——你只要换配置文件基本就能切换策略类型
    • 端到端训练/评估流程（lerobot-train/eval）:训练脚本、在线评估(接 gym 环境)、可视化工具、checkpoint 管理这些都打包好了,你要做的更多是配置和调参,而不是从零搭工程链路

  • 接触密集型操作（Contact-Rich Manipulation）为什么视觉不够用

    • 物体可能被手遮挡
    • 需要判断有没有对齐、力度够不够、是否打滑

  • 触觉能提供的信息类型

    • 接触力/摩擦/滑动/接触状态转移

硬件基础

  • 视觉触觉传感器

    • GelSight/DIGIT 等，原理：形变→内置摄像头成像
    • 传感器内部有一层软胶皮肤，接触变形后由内置摄像头拍照，再通过图像处理/深度学习还原出接触形状、压力分布甚至滑动信息。
    • 本质上是把触觉问题转换成了图像问题，所以能直接复用视觉模型的架构（这也是为什么很多论文能把触觉塞进 VLA/世界模型里）

  • 力/压力传感器类（直接输出物理量，非图像）

  • 传感器异构性问题（型号/分辨率/安装位置不同导致的迁移难题）

模型范式

  • VLA（Vision-Language-Action）

    • 基本框架：观测 (O = V + L) -> 动作 (A)
    • 输入为
    • 输出为机器人动作序列（关节角度/末端为姿等）

  • VTLA（Vision-Tactile-Language-Action）

    • VLA基础上的扩展，加入tactile sensors
    • 问题：触觉信号怎么编码、怎么和VL对齐、怎么融合进动作生成

  • World Model

    • 路线：预测”下一步会怎样”，用于生成数据/规划/闭环校正
    • O_t + A_t -> O_t+1
    • 世界模型可以做：
    • ① 数据增强/生成虚拟 rollout 训练数据；
    • ② 做 planning（在脑内试错，选最优动作再执行）；
    • ③ 做闭环校正（预测和真实触觉对不上时立刻纠偏）

表征与编码

  • Encoder 的含义
    特征提取器（一段神经网络），区别于物理编码器（位移/角度编码器）

  • 特征向量/embedding 的产生方式

    • 离散的L信息（通过tokenizer划分成token）通过embedding table（形状为[词表大小, 向量维度]的矩阵）方式获得初始向量（查找token对应的一行）
    • 连续的VT信息均通过特定训练的一段神经网络（encoder）得到特征向量（这个特征空间可以是语义空间（类似CLIP embedding做对齐），也可以是单独适配该encoder的空间）
    • 连续信号靠网络计算 vs 离散 token 查 embedding table

  • CLIP

    • CLIP：用对比学习方法训练的模型，用大量”图片-文字”配对数据,让匹配的图文对在共享空间里靠近、不匹配的推远,训练完之后就能把图片和文字都编码到同一个语义空间里。
    • CLIP embedding：用CLIP模型算出的向量，即以图片/文字为输入，经过CLIP图像编码器/文字编码器得到的向量。

  • 多模态对齐的本质：不同模态最终都变成同一空间下的向量/token


模态融合方式

  • 早期融合 vs 晚期融合

    • 早期融合：各模态经过modality-specific encoder后，进入 backbone 前就合并。
    • 中期融合：各模态先独立进入 backbone，在 backbone 内用 self-attention / cross-attention 交互。
    • 晚期融合：各模态分别经过大部分 backbone，接近 action head 时再合并。
    • 目前很多 VLA 中，V+L 通常较早进入同一 backbone 做联合建模；state / proprioception 则常作为额外 conditioning，在 backbone 中后段或 action head 中注入。
    • proprioception 即本体感觉（机器人自身状态信息robo_state），包括关节位姿、速度、夹爪状态等，为 state 的子集，state 还可能包括任务状态、历史状态、环境状态等。

  • fusion 层级

    • input-level fusion
    • Feature-level fusion
    • Token-level fusion (token也是feature向量的一种，但token含语义信息，因此是语义空间中的fusion。但不一定经过了对齐，因此不一定是同一语义空间的fusion)
    • Conditioning / modulation：不直接拼 token，而是用 state/tactile 去调制 hidden state，比如 FiLM、AdaLN。
    • Decision/action-level fusion：各模态甚至各自先得到独立决策，最后在 action head 或 controller 合并，属于更晚期融合。

  • Cross-attention / cross-view attention

    • 若采用晚期融合，可以新增一个触觉编码器 + 新增的 cross-attention 层。
    • 例如触觉token做Query，视觉token做Key/Value

  • Contact-aware fusion

    • 根据接触状态动态调整融合权重（包括VTL等信息的权重 & 每种信息中某特定部分的权重，比如图像中的某部分）

训练范式

  • 自监督预训练（对比学习、掩码重建——针对 encoder，无需动作标签）

    • 有动作标注的数据很稀缺，但无标签的数据很容易采集。因此在训练encoder时，往往可以先用无标签的数据，使之学会”怎么把原始信号压缩成有语义的特征向量”，后续可以冻结或微调encoder
    • 常见方法：
    • 对比学习（比如让同一时刻拍到的触觉图和视觉图的向量距离拉近，不同时刻/不同物体的推远，类似 CLIP 的思路）；
    • 掩码重建（遮住触觉图的一部分，让模型学着补全，类似 MAE）。这两种都不需要动作标签。

  • 模仿学习/行为克隆（针对策略本身，需要示教数据里的动作标签）

  • 微调 vs 全量微调 vs LoRA（后训练阶段的几种方式及各自代价）

    • 微调为“后训练”中的一种，在VLA中是指拿成熟的VLM模型，在自己的小规模机器人数据上训练，进而适应具体任务。
    • 全量微调是指，模型中所有参数都参与更新。效果通常最好但显存/算力开销大，而且容易”灾难性遗忘”（把预训练学到的通用知识冲掉）
    • LoRA：冻结原始权重，只在部分层（通常是注意力层）旁边插入两个小的低秩矩阵，只训练这两个小矩阵，参数量可能只有原模型的 0.1%~1%

动作生成机制

  • Diffusion Policy
    • 用去噪过程建模多峰动作分布
    • Policy即策略，用于 VLA 的 Diffusion model
    • 很多任务里”正确动作”不是唯一的，比如绕开障碍物可以往左也可以往右，这叫动作分布是多峰的（multimodal）。如果用普通回归去拟合多峰分布，模型会学出”左右取平均”这种谁都不对的动作。
    • 扩散模型天生擅长建模复杂/多峰分布（它本质是在学一个概率分布，而不是学一个确定的函数）。所以 Diffusion Policy 就是：把”给定观测，生成一段动作”这件事，做成”以观测为条件，从噪声去噪出动作序列”的扩散过程。
    • V + L + State（state 也可能在 head 中加入） -> VLA backbone -> head -> Diffusion action head -> Action chunk
  • Action Chunking（一次生成一段动作，receding horizon 执行）
    • 核心思路：模型不是逐帧预测单个 action，而是一次性生成一段未来动作序列（action chunk，长度记作 horizon），比如未来 16 步。
    • 为什么不逐帧预测：
      • 逐帧预测容易产生复合误差累积（compounding error）——每一步的小误差会传递到下一步，长时间执行后轨迹漂移严重；
      • 一次预测一整段序列，模型能在 chunk 内部保持动作的时序一致性（比如推方块时保持连贯的推的方向，而不是每步各自为政）。
    • 但不会整段执行完：生成的 horizon 步动作里，实际只执行前面 n_action_steps 步（比如 horizon=16，只执行前 8 步），然后：
      1. 获取新的观测（observation）；
      2. 丢弃剩余未执行的动作；
      3. 基于新观测重新生成一段新的 action chunk。
    • 这个”预测长、执行短、滚动重规划”的模式就叫 receding horizon（也叫 rolling replanning / model predictive control 的思路）。

控制与反馈

  • 开环执行的盲区（action chunk 执行期间为何”看不见”新变化）

    • 如果一次生成一个action chunk，执行完这一整段才重新看新观测”——这一整段执行期间，模型对新的触觉变化是”看不见/不响应”的，是开环执行

  • 高频反射式校正（低层快速闭环 vs 高层慢速规划的分工）high frequency feedback

    • 可单独设计一个小模块，比较”世界模型/上一步预测的触觉信号”和”传感器实际测到的触觉信号”，如果有偏差（比如实际接触力比预测的大很多，说明可能要打滑了），就在当前正在执行的动作 chunk 上做一个小幅度的实时修正，而不必等下一次完整的大模型推理。
    • 大模型的完整推理循环像是”深思熟虑做计划”，而这个高频反射校正更像是人被烫到时的脊髓反射——不用等大脑（VLA）反应过来，先做个快速的局部纠正动作。

数据处理

  • 遥操作采集及其成本问题

    • 遥操作（teleoperation）可以粗暴理解为遥控机器人工作来采集数据

  • Robot-free / 免机器人采集方案

    • 新兴方法是直接用手持设备采集视触觉数据。比如让环卫工人每天带上专用手套获取大量样本。但此类方法问题是如何解决“人手采集数据和机器人执行时数据的差异”。

  • 多模态时间同步（视觉/触觉采样率不一致）

  • 跨传感器数据归一化

近期工作

OmniVTLA（如何把Tactil表征得更像VL语义）

  • 数据处理：搭建ObjTac数据集，用视觉/语言给 force-based tactile 建立语义监督，即针对不同物体对齐VTL信息。具体流程：采力、采视频、打语言标签（包含物体多方面特征）、对齐时间戳、得到物体VTL三模态对齐数据
  • 模型创新点：提出 dual-encoder 来处理触觉信息：
    • ViT encoder：force map → image-like representation → ViT → tokens（ViT即Vision Transformer，常用作image encoder）
    • SA-ViT encoder：提前用 V-T-L 对比学习做语义对齐，训练出输出向量和VL信息对齐的tactile encoder
  • VLA backbone接收的五路输入：Language tokens、encoded image、tactile → 普通 ViT → tactile features、tactile → SA-ViT → VL-aligned tactile features（为了让模型更好地适应触觉信息）、robot state / proprioception

Tactile-VLA

  • 数据处理：直接采机器人数据，用带双触觉传感器和相机的UMI采集器，同时记录视觉、触觉、语言指令、proprioception和expert action。
  • 模型创新点：
    • tactile处理：最近n帧触觉历史拼起来 -> MLP encoder -> 一个tactile token
    • 模态融合方式：V/T/L token concat 成一个prefix（前缀），在 pretrained VLM 里共同 attention。属于比较典型的 early/token-level fusion。
    • Action侧创新：
      • Tactile-aware action expert：在flow matching基础上设计的action head
      • Hybrid position-force controller：接在action expert后，负责把expert输出的position和force target执行
